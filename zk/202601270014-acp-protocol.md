# ACP Standardizes Agent Communication

The Agent Client Protocol (ACP) is a standardized interface that enables CodeCompanion to
communicate with autonomous coding agents. Unlike stateless LLM interactions, ACP
sessions are stateful, allowing agents to maintain context, execute tools, and manage complex
multi-step workflows.

## Core Capabilities

1. **Stateful Sessions:** The agent maintains the conversation history and context.
   CodeCompanion only sends new messages, not the full history.
2. **Tool Execution:** Agents can discover and execute client-side tools (like
   file reading/writing) via the protocol.
3. **Permissions:** A robust permission system allows users to approve or reject
   agent actions, particularly file modifications.
4. **Mode Management:** Sessions can switch between different modes (e.g., "Ask",
   "Architect", "Code") to tailor the agent's behavior.

## Integration

The ACP implementation sits alongside HTTP adapters but operates differently:
- **Transport:** Uses standard IO (stdio) or other transports to communicate with
  agent processes.
- **Protocol:** Implements the ACP specification (JSON-RPC) for message exchange.
- **Capabilities:** Advertises client capabilities (e.g., file system access) to
  the agent during initialization.
